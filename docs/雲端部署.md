# MPDL 雲端網頁 App

雲端版將相同的熊恩系列介面、Python 後端、yt-dlp、Node.js 與 FFmpeg 包在一個 Docker 服務裡。部署成功後，使用者開 HTTPS 網址就能下載，不需要啟動 Mac，也不需要同一個 Wi-Fi。

目前程式已提供雲端模式及 Railway 部署設定；正式網站網址以雲端平台實際部署完成的回傳結果為準。

## Railway

1. 在 Railway 授權使用 GitHub 的 `SeanChen0427/MPDL` 儲存庫。
2. 建立從 GitHub 部署的服務，選擇 MPDL。平台會採用根目錄的 `Dockerfile` 與 `railway.json`。
3. 保持一個執行個體，部署後產生公開 HTTPS 網域。健康檢查為 `/healthz`。
4. 開啟產生的網址，確認「已連接雲端」，再實測自己的影片與儲存檔案。

本次對話可透過 Railway 連接來執行部署；尚未授權帳號時，不會宣稱網站已上線。主機方案與費用依帳號顯示的資源、流量及方案而定。

## 本機驗證容器

```sh
docker build -t mpdl .
docker run --rm --name mpdl -p 8080:8080 mpdl
```

`/healthz` 可在 `http://localhost:8080/healthz` 驗證元件。瀏覽器雲端模式使用 Secure Cookie，正式環境必須透過 HTTPS。`localhost` 是否允許 Secure Cookie 依瀏覽器規則；測試登入狀態時優先使用 HTTPS。

## 執行設定

| 變數 | 用途 |
| --- | --- |
| `PORT` | 雲端平台分配的 HTTP 埠號；容器預設 8080 |
| `TUBEDROP_MODE` | `cloud` 啟用雲端模式；Mac 啟動入口預設本機模式 |
| `TUBEDROP_DOWNLOAD_DIR` | 容器暫存目錄，預設 `/tmp/mpdl-downloads` |
| `TUBEDROP_PUBLIC_URL` | 選填，使用額外反向代理且需指定瀏覽器正式來源時，設定完整 HTTPS 網域，不加路徑 |
| `TUBEDROP_PYTHON` | 下載元件的 Python 路徑，Docker 已設定 |

## 雲端與本機差異

- 雲端開首頁時簽發 HttpOnly、Secure、SameSite=Strict Cookie，不需要輸入啟動碼。每個瀏覽器只可讀取、取消、儲存自己的下載工作。
- HTTPS 反向代理來源可正常提交下載；其他網站的 POST 會拒絕。
- 介面依後端模式顯示「Mac」或「雲端」，分享網址與手機說明同步切換。
- 雲端已結束工作與暫存檔在完成約一小時後清理；清理週期一分鐘。本機既有下載檔案不會因此清除。
- 雲端工作狀態在記憶體、檔案在暫存磁碟。重啟、重新部署或平台回收執行個體後，舊記錄可能失效；需及時儲存檔案。
- 保持單一執行個體；目前未使用跨主機佇列或物件儲存。
- 平台可能對雲端主機 IP 要求登入或反機器人驗證；本機成功下載不代表所有雲端機房也能取得同一支影片。需在實際部署環境驗證。
